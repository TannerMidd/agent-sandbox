01 / System architecture

Separation is a feature.

Five production assemblies keep UI, policy, orchestration, operating-system integration, and elevated work from collapsing into one trust domain. A standard-library Python helper runs on demand inside the guest and never listens on a port.

L-01AppAccessible XAML views, MVVM commands, navigation, and dependency composition.
L-02DomainImmutable records, resource rules, guest-path policy, operation states, and versioned contracts.
L-03ApplicationSetup coordination and narrow service interfaces; workflow order without process details.
L-04InfrastructureSafe arguments, Multipass discovery, lifecycle, settings, terminals, presets, and staged transfers.
L-05Setup HelperSeparately compiled elevation surface with a fixed operation allow-list and protected named pipe.
L-06Guest HelperDaemonless, standard-library file operations invoked per request through multipass exec.

02 / Trust boundaries

Authority stays narrow.

The desktop process runs as the current user. Elevation is isolated, the hypervisor executable is verified, and guest inputs use structured data rather than interpolated command strings.

B-01 // ELEVATION

Current user → administrator

An ACL-protected named pipe admits only the current user and local Administrators. The helper validates schema version and rejects anything outside its compiled operation allow-list.

B-02 // PROCESS

Application → Multipass

Multipass must resolve from its canonical Program Files path or carry verified Canonical/Multipass version metadata. Arguments use ProcessStartInfo.ArgumentList, never a shell.

B-03 // GUEST

Windows host → Linux VM

Guest file requests encode paths as component arrays. Separators, dot segments, NUL, symlink parents, special files, root escape, and stale expectations are rejected.

B-04 // FILES

Untrusted guest → host

Transfers are staged and verified before commit. Reparse points, unsafe archives, unbounded extraction, and silent conflicts fail closed. Returned files still remain untrusted.

03 / Provisioning lifecycle

A checkpointed state machine.

The coordinator records each meaningful state. Relaunching does not guess—it re-inspects the host and selects the next safe transition.

Inspect prerequisites

Confirm Windows edition, virtualization, Hyper-V, memory, disk, and a trusted Multipass installation.

Resolve the plan

Validate a compiled catalog image or advanced HTTPS cloud-image URL, native x64 architecture, resources, hardening, and presets.

Render temporary policy

Insert the chosen update, sysctl, audit, privilege, SSH, firewall, and egress controls into packaged cloud-init markers. Invalid combinations fail closed.

Launch and attest

Create the VM, wait for cloud-init, then verify /etc/agent-sandbox/hardening.json during the health check.

Capture known-good state

Remove temporary host material, stop the VM, create the exact clean snapshot, and restart.

Install optional tooling

Only after the baseline exists, install online agent presets with exact versions and integrity metadata. Offline policy intentionally skips this step.

04 / Guest file protocol

Structured paths, versioned requests.

The guest workspace protocol favors explicit components and bounded operations. Unknown schema versions fail closed, and no long-running bridge service expands the attack surface.

CONCEPTUAL REQUEST // SCHEMA V1JSON
{
  "version": 1,
  "operation": "copy_out",
  "source": {
    "components": ["project", "build", "report.json"],
    "expectedRevision": "sha256:…"
  },
  "conflictPolicy": "fail"
}
  • PATH COMPONENTSNo separators, dot segments, NUL bytes, or root escape.
  • FILESYSTEM TYPENo traversal through symlinks; special files are rejected.
  • BOUNDED WORKPages, archive entries, extraction size, and operation scope are capped.
  • ATOMIC COMMITTransfers stage first; destination conflicts never silently overwrite.

05 / Security invariants

Fail closed at every seam.

These are implementation constraints, not marketing promises. The project threat model is explicit about both protected flows and non-goals.

  • EXACT TARGETSLifecycle and recovery act only on VMs created by the app; legacy import accepts exactly agent-dev.
  • NO SHELL STRINGSUser-controlled paths and instance names are passed as distinct process arguments.
  • NO HOST SECRETSAgent authentication occurs inside the VM; host credential forwarding is out of scope.
  • NETWORK BASELINEEvery new VM denies unsolicited inbound traffic and root/password SSH login.
  • LOCAL DATASettings and redacted operation logs stay local; there is no telemetry or silent updater.
  • HONEST BOUNDARYThis is a development isolation boundary—not hostile multi-tenant or malware-analysis containment.

06 / Stack & verification

Typed where it matters.

The production application is C#/.NET—not a PowerShell GUI. Legacy scripts remain non-authoritative and are neither elevated nor invoked by release builds.

Release posture

Development preview, deliberately.

Core workflows and automated suites are implemented. Public beta approval remains gated on broader Appium interaction coverage, accessibility testing, and the physical Windows hardware matrix.
